Prismio 0.3.0 makes everyday code shorter. Structs nest, `let` takes a struct or a tuple apart, `if` and `match` give values, and the `?` operator, `if let`, `while let` and `let ... else` stop optionals and `Result`s from needing a block of boilerplate. `match` takes guards, range patterns, string patterns and patterns inside a variant's pattern, and `HashMap` and `HashSet` are rebuilt around owned values.

It is still pre-1.0. The `HashMap` and `HashSet` API changed, a struct stored in a map must now be `Copy`, and an arm after `_` is an error, so read [Breaking changes](#breaking-changes) before upgrading a program written for 0.2.0. [Migrating from 0.2 to 0.3](/migration/0.2-to-0.3) has the before and after for each one.

## Downloads

| Platform | Archive | Needs |
|---|---|---|
| macOS (Apple silicon) | `prismio-0.3.0-macos-arm64.tar.gz` | macOS 14 or later for the compiler; programs it builds run on macOS 11 or later |
| Linux (x86-64) | `prismio-0.3.0-linux-x64.tar.gz` | glibc 2.38 or later for the compiler; programs it builds need glibc 2.34 or later |
| Windows (x86-64) | `prismio-0.3.0-windows-x64.zip` | Visual Studio Build Tools and the Windows SDK (see below); no Visual C++ redistributable |
| Linux (ARM64) | `prismio-0.3.0-linux-arm64.tar.gz` | glibc 2.38 or later for the compiler; programs it builds need glibc 2.34 or later |
| Windows (ARM64) | `prismio-0.3.0-windows-arm64.zip` | the same build tools as x86-64 |

Each archive has a `.sha256` beside it. **The archives are not signed**: the checksum shows the download is intact, not who made it, so take both from this release page. On macOS and Linux the installer does this for you and refuses an archive that does not match:

```bash
curl -fsSL https://prismio.org/install.sh | sh
```

On Windows, unpack the `.zip` and put its `bin` directory on `PATH`. The compiler carries its own LLVM but links programs with the system's linker, so you also need the platform's C tools: the Xcode Command Line Tools on macOS, `cc` and the C library headers on Linux (`build-essential` on Debian and Ubuntu), or Visual Studio Build Tools with the **Desktop development with C++** workload on Windows. The macOS, Linux x86-64 and Windows x86-64 archives are built and tested by the project's CI. **The two ARM64 archives are built and tested on virtual machines**, so they have had less use. There is no archive for Intel Macs; build from source (see the [installation guide](/start/installation#build-from-source)).

## Highlights

- **Nested structs, destructuring `let` and tuples.** `size: struct { w: Int, h: Int }`, `let Point { x, y: b, .. } = p`, and `(Int, String)` with `t.0` and `let (a, b) = t`.
- **`if` and `match` as values.** `let sign = if n < 0 { -1 } else { 1 }`, and `return match c { Color.Red => "red", _ => "?" }`.
- **The `?` operator.** `let n = parse(s)?` is the `Ok` value of a `Result`, or an early `return Result.Err(e)`; on an optional it is the value or an early `return none`.
- **`if let`, `while let` and `let ... else`.** Take an optional's value or an enum's payload where you test for it.
- **A larger `match`.** Guards, range patterns, string patterns, patterns inside a variant, and no parentheses around the value.
- **`HashMap` and `HashSet` grow up.** `m[key] = value`, owned values, `getOrInsert`, `upsert`, `modify`, `take`, `retain`, `reserve`, `shrinkToFit`, and the set algebra: `union`, `intersection`, `difference` and more.
- **Editor support for all of it.** The semantic index, hover, hints and completion understand nested structs, tuples and the new patterns.

## What is new

### Language

- **[Nested structs](/language/structs).** A struct can declare another inside it, as a field's type (`size: struct { w: Int, h: Int }`) or between the fields (`struct Limits { ... }`). It is reached as `Outer.field` or `Outer.Limits` in a type, a literal or an `impl`, and `{ w: 1, h: 2 }` is a struct literal wherever the expected type is a struct. Not yet inside a generic struct.
- **Destructuring `let`.** `let Point { x, y: b, .. } = p` binds fields by name, patterns nest, `mut` makes the bindings assignable, and `_` skips a field. Not in `match` arms or parameters.
- **[Tuples](/stdlib/tuple).** `(Int, String)`, `(a, b)`, `t.0` and `t.0.1`, and `let (a, b) = t`, from two to four elements. A tuple is `Tuple2` to `Tuple4` from the new `std.tuple`, is `Copy` and `Eq`, and a file that writes one imports `std.tuple` itself.
- **[`if` and `match` as values](/language/control-flow).** A branch is one expression, an `if` needs its `else`, and a `match` covers every value. They are refused where they could not run first: after a call in the same statement, in a loop header, on the right of `and`, `or` or `??`, in an `else if` condition, in a closure's expression body and in a global `let`.
- **[The `?` operator](/language/error-handling).** The function must return a matching `Result` (the same error type) or optional. The rest of the block runs inside the success arm, so an owned payload stays owned.
- **[`if let`, `while let` and `let ... else`](/language/control-flow#if-let-and-let--else).** A name is an optional's value and a variant pattern is an enum's payload. A `let ... else`'s `else` must leave the block with `return`, `break`, `continue` or `panic`, which the compiler checks.
- **[`match`](/language/pattern-matching) without the ceremony.** `match s { ... }` needs no parentheses around the value, an arm may be a single statement without braces, and an arm may be empty (`_ =>`). The old spellings still read.
- **Guards, range patterns and string patterns.** `Shape.Circle(r) if r > 10 =>`, `1..9 =>` (the end included), `10..<100 =>`, and `"stop" =>` on a `String`. A `match` that has any of these ends in an unguarded `_`.
- **Patterns inside a variant's pattern.** `Outer.Wrap(Inner.A(v)) =>`, `Outer.Plain(7) =>` and `_` to skip a value, at any depth, in `match`, `if let`, `while let` and `let ... else`.

### Standard library

- **[`HashMap` stores with `m[key] = value`](/stdlib/map).** It inserts or replaces. `m[key]` still panics on a missing key and `m.get(key)` answers an optional.
- **`getOrInsert`, `getOrInsertWith`, `getOrInsertDefault`, `upsert` and `modify`.** The `entry` idioms as methods, each one lookup: `counts.upsert(word, 1, |n: Int| n + 1)`, and `groups.modify(key, |inout v: Vec<Int>| { v.push(x) })` changes a stored `Vec` in place.
- **More `HashMap`.** `update`, `take`, `retain`, `reserve`, `capacity` and `insert`, with the value `set` replaced handed back.
- **A fuller `HashSet`.** `for key in set`, `get`, `take`, `toggle`, `retain` and `reserve`, the set algebra (`union`, `intersection`, `difference`, `symmetricDifference`, `isSubsetOf`, `isSupersetOf`, `isDisjoint`), and `insertAll`, `removeAll` and `retainAll` over a set or a `Vec`.
- **`shrinkToFit`** on `Vec`, `HashMap` and `HashSet` gives back the capacity past the length.
- **`Hash` and `Hasher` in `std.key`.** A composite key feeds its fields to a hasher with `writeInt`, `writeWide`, `writeBool`, `writeChar` and `writeString`, instead of folding them by hand.

### Tooling

- **Editor support for the new syntax.** The semantic index nests a struct under its owner and finds its fields by path, indexes a pattern's new name, prints a tuple as `(Int, String)` in hover, hints and messages, and completes the structs inside `Window.`.
- **`--strict-float`** (and `strictFloat` in a manifest's `profiles` block) keeps every float add in source order. See [Performance](#performance).
- **`prismio fmt`** no longer joins `, ..}` in a destructuring pattern into `,..}`.

## Breaking changes

- **A `HashMap` holds owned values, so a struct value must write `impl Copy`.** `HashMap<String, String>`, `HashMap<Int, Vec<Int>>` and a map of structs that own a `String` compile and run with no leaks, but the value type is now bound by `Copy`, as the key is by `Key + Copy`. Without it the error is *`Report` does not implement `Copy`*. Scalar values are unchanged.
- **`HashMap`'s storing API changed.** `m.set(key, value)` answers the value it replaced (`V?`, `none` for a new key) where it answered a `Bool`, and the new `m.insert(key, value) -> Bool` stores only a new key and says whether it was new. `length` is `count` and `has` is `contains` on `HashMap`, and `length` is `count` on `HashSet`.
- **The free functions behind `HashMap` are gone.** `mapSet`, `mapGet`, `mapGetOr`, `mapHas`, `mapRemove`, `mapClear`, `mapIndexOf` and `mapUpdate` are deleted; use the methods.
- **An arm after `_` is an error.** `_` matches everything, so an arm after it can never run. The compiler says so ("comes after `_`") for an integer, enum or payload `match`.
- **A float loop reduction may be summed in any order.** A `Float` or `F32` local that a loop only adds into (`x += e`, `x -= e`, `x = x + e`, `x = x - e`, with `e` not reading `x`) may now be added in any order, so the sum can split across SIMD lanes. NaNs, infinities and signed zeros are untouched, but the last bits of a sum can differ from a sequential sum, and from one target to another. Build with `--strict-float` for the source-order sum.

## Fixed

- **Returning a value unwrapped with `expect` freed it first.** `let s = expect(q); return s` released `q` at the `return`, so the caller got freed memory. It was reachable through `?` on an optional followed by `return s`.
- **A `match` arm after `_` was invalid IR.** It is now an error, as above.
- **A `HashMap`, a `HashSet` or any generic struct in a field of a struct is released once, by the struct.** A map returned inside a struct used to crash on its first read, and a map literal written in the field leaked its keys and values.
- **Owned temporaries that leaked are released.** A `String` field compared in place on an owned struct, a scalar element read off an owned `Vec` on the right of `or` or in a `while`, and a struct literal written inline as the argument of a function, among others.
- **A displaced or removed element is released at the store.** A value replaced in a `HashMap`, a key or value removed, and an element of any private `Vec` field the compiler can prove is not read through a view, used to be kept until the container died.
- **A map literal with computed owned keys or values leaked** in a field or a `return`, and a literal of thirty entries leaked its values.
- **`make().names.length` and `make().name.length`** released nothing where the struct could not be bound ahead of the statement.

## Performance

- **A program that never starts a thread is smaller.** The allocator's thread-local setup and a 16 KiB page are no longer linked in: over the 337 buildable test programs, the total went from 19.90 MB to 14.06 MB (a mean of 59,062 to 41,718 bytes). A program that does spawn is unchanged.
- **Float sums vectorize.** In the hosted benchmark suite `numerical_integration` runs in 1.1 ms (0.51× of C++ and 0.52× of Rust), and the new `float_sum` in 2.2 ms (0.20× and 0.21×) and `float_dot` in 4.2 ms (0.33× and 0.37×). Built with `--strict-float` the three land on C++ at 1.00×, 0.94× and 0.91×. C++ and Rust both keep a plain sum sequential, so the same loop stays scalar there. See [Float loop reductions](https://developers.prismio.org/compiler/float-reductions).
- **`HashMap` costs the same.** The update loop measured 39.2 ms against 39.1 ms before, and remove-and-reinsert 45.7 ms against 46.7 ms.

## Known limits

- **A task is still an operating-system thread.** `await` blocks its thread when the task it awaits is running elsewhere, and a held `Future` or a task takes at most three arguments.
- **Nested structs are not allowed inside a generic struct.** Destructuring does not work in `match` arms or in parameters.
- **Some temporary shapes still leak.** A payload enum built both as a stack literal in an argument and by a function leaks the function's inner payload. `--verify` reports these as `leaked` with no violation.
- **A column used with `pop`, `removeAt`, `sorted` or another `std.vec` function, or whose field is `public`, still keeps its removed elements until the container dies.**
- **Windows is the least exercised platform.** Some Windows-only paths are verified by CI alone.
- Diagnostic codes are not yet stable.

Exact diagnostic prose, AIF report shape, source syntax, runtime ABI and package layout remain pre-1.0 and may change.

## Not included

Networking, regex, mutexes and other synchronization types, a work-stealing executor, user-written lifetimes, exceptions, macros, and a package **registry** and version solving.

**WebAssembly is blocked, not in progress.** Prismio emits wasm32 IR, but there is no C library for `wasm32-unknown-unknown`, so the runtime cannot be built for it.
