Most 0.2 programs build with 0.3.0 unchanged. The changes below touch programs that use a `HashMap` or `HashSet`, write a `match` with an arm after `_`, or add floats in a loop. The [release notes](/releases/0.3.0) list everything that is new.

To find the places a program needs attention, build it and read the first errors:

```bash
prismio check src/main.psm
```

## `HashMap` and `HashSet` method names

`m.set(key, value)` answers the value it replaced, an optional that is `none` for a new key, where it answered a `Bool`. The new `m.insert(key, value)` stores only a new key and answers whether it was new. `length` is `count` and `has` is `contains` on a `HashMap`, and `length` is `count` on a `HashSet`.

<!-- prismio-check: pass -->
```prismio
import std.io
import std.map
import std.option

fn main() -> Int {
    let m: HashMap<String, Int> = {}
    let wasNew = m.set("a", 1) == none      // 0.2 answered a Bool here
    println(wasNew)
    println(m.insert("a", 2))                // false: stores only a new key
    println(m.count)                         // was m.length
    println(m.contains("a"))                 // was m.has("a")
    let s: HashSet<Int> = HashSet()
    s.insert(1)
    println(s.count)                         // was s.length
    return 0
}
```

`m[key] = value` is new: it inserts or replaces. Reading `m[key]` still panics on a missing key, and `m.get(key)` answers an optional.

## The free functions behind `HashMap` are gone

`mapSet`, `mapGet`, `mapGetOr`, `mapHas`, `mapRemove`, `mapClear`, `mapIndexOf` and `mapUpdate` are deleted. Call the method instead: `m.set`, `m.get`, `m.getOr`, `m.contains`, `m.remove`, `m.clear` and `m.update`.

## A struct stored in a `HashMap` must be `Copy`

A `HashMap` now owns its values and answers a copy from every read, so the value type must implement `Copy`, as the key type must implement `Key + Copy`. A scalar value needs nothing. A struct that owns a `String` or a `Vec` writes `impl Copy` with a `copyOf` that duplicates what it owns. Without it the error is *`Report` does not implement `Copy`*.

<!-- prismio-check: pass -->
```prismio
import std.io
import std.map
import std.copy

struct Report {
    title: String,
    pages: Int,
}

impl Copy for Report {
    fn copyOf(self) -> Report {
        return Report { title: copyOf(self.title), pages: self.pages }
    }
}

fn main() -> Int {
    let reports: HashMap<Int, Report> = {}
    reports[1] = Report { title: "one", pages: 3 }
    println(reports[1].pages)
    return 0
}
```

## An arm after `_` is an error

`_` matches everything, so an arm after it can never run. 0.2 accepted it and produced invalid code for some shapes. Move the arm above `_`, or delete it.

<!-- prismio-check: fail -->
```prismio
fn name(n: Int) -> String {
    match n {
        0 => "zero",
        _ => "other",
        1 => "one",      // error: this arm comes after `_`
    }
}

fn main() -> Int {
    return name(1).length
}
```

## Float sums in a loop may be added in any order

A `Float` or `F32` local that a loop only adds into (`sum += x`) may now be summed in any order, which lets the compiler split the sum across SIMD lanes. NaNs, infinities and signed zeros are untouched, but the last bits of the result can differ from a sequential sum, and from one target to another. Build with `--strict-float`, or set `strictFloat = true` in a `profiles` block, to keep every add in source order.

## Declare the new minimum in `build.ums`

A project that asks for `prismio = "0.2.0"` still builds. Raise the line to `prismio = "0.3.0"` once the program uses a 0.3 feature, so an older compiler refuses it with a clear message.
